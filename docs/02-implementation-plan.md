# 对话人格陪伴产品实施方案

> 文档状态：Draft  
> 实施目标：交付 V1.0 Web MVP，并为 V1.1 微信小程序预留渠道层  
> 更新时间：2026-07-30  
> 关联文档：[V1 PRD](./01-prd-persona-companion-mvp.md) · [技术方案](./03-technical-design.md)

## 1. 实施原则

1. 先验证人格效果，再接微信渠道。
2. 先做模块化单体，不在 V1 拆分大量微服务。
3. 先做外部人格和记忆系统，不在 V1 微调模型。
4. 人格结论必须可解释、可修改、可回滚。
5. AI 输出默认不参与人格学习。
6. 从第一天保留离线评估集和基线。
7. 数据删除、安全隔离和审计属于主流程，不是上线前补丁。

## 2. 实施范围

### 2.1 V1 交付范围

- Web 管理与聊天客户端。
- 后端 API。
- 聊天记录导入和清洗。
- 人格构建任务。
- 人格、关系、记忆和范例管理。
- 对话生成。
- 像 / 不像反馈。
- 候选人格更新。
- 人格版本与回滚。
- 用户数据删除。
- 基础安全、日志、指标和部署。

### 2.2 V1.1 范围

- 微信小程序客户端。
- 微信登录或账号绑定。
- 微信渠道适配器。
- 消息同步和渠道限流。

### 2.3 明确排除

- 普通个人微信号 Hook 或协议逆向。
- 语音克隆和实时语音。
- 自动对第三方发消息。
- 无审核的人格自动学习。
- 多 Agent 自主讨论。

## 3. 阶段划分

## 阶段 0：产品与数据样本准备

### 目标

确定人格效果如何衡量，并获得一份可以合法用于开发测试的聊天样本。

### 工作项

- 定义标准消息格式。
- 确认首个聊天导出格式。
- 准备脱敏测试样本。
- 从样本中留出测试集。
- 定义人格基线方案：单一长 Prompt。
- 制定数据授权和删除流程。
- 定义内容安全边界。

### 交付物

- `message-schema-v1.json`。
- 一份脱敏样本数据。
- 基线人格 Prompt。
- 首版评估题集。
- 数据使用确认文案。
- 风险场景清单。

### 验收

- 样本参与者身份明确。
- 测试集未被人格构建流程使用。
- 测试数据不包含密码、令牌等机密。

## 阶段 1：项目骨架与基础设施

### 目标

建立可本地运行、可测试、可部署的工程基础。

### 工作项

- 初始化前后端工程。
- 配置 PostgreSQL、pgvector 和 Redis。
- 建立数据库迁移。
- 建立登录和租户隔离。
- 建立对象存储抽象。
- 建立异步任务队列。
- 建立模型网关接口。
- 建立开发、测试、生产配置。
- 建立 CI：格式检查、类型检查、单元测试和迁移检查。

### 交付物

- 单仓或结构清晰的多包仓库。
- Docker Compose 本地环境。
- 数据库初始迁移。
- 健康检查接口。
- OpenAPI 文档。
- CI 配置。

### 验收

- 新开发者可以按 README 在本地启动完整环境。
- API、数据库、Redis 和任务 Worker 均能通过健康检查。
- 测试环境与生产环境密钥不进入代码仓库。

## 阶段 2：导入与清洗

### 目标

把用户上传的聊天记录转换为可靠的内部消息数据。

### 工作项

- 文件上传和存储。
- JSONL 解析器。
- 首个微信转换格式解析器。
- 参与者统计和身份确认。
- 消息指纹和去重。
- 系统消息过滤。
- 时间格式标准化。
- 连续消息合并与会话分段。
- 敏感信息扫描。
- 清洗报告。
- 导入任务状态和失败重试。

### 交付物

- 导入 API。
- 上传和身份确认页面。
- 清洗报告页面。
- 解析错误报告。
- 导入任务测试集。

### 验收

- 对标准样本解析成功率达到约定阈值。
- 重复导入不会产生重复消息。
- 目标人物与当前用户未确认前不能开始构建。
- 群聊数据会被识别并阻止进入 V1 构建。

## 阶段 3：人格构建器

### 目标

从真实聊天中生成人格初稿，并保留来源证据。

### 工作项

- 对话片段切分。
- 场景标签分类。
- 表达风格统计。
- 人格候选提取。
- 关系候选提取。
- 共同记忆提取。
- 对话范例质量筛选。
- 向量索引。
- 冲突与低置信度标记。
- 评估集留出。
- 人格初版打包。

### 推荐构建顺序

```text
确定性统计
→ 小批次 LLM 提取
→ 候选聚合
→ 证据校验
→ 冲突检测
→ 人格摘要
→ 用户审核
→ 发布 v1.0.0
```

### 交付物

- 人格构建任务。
- 人格画像页面。
- 关系画像页面。
- 共同记忆页面。
- 对话范例页面。
- 人格数据包导出。

### 验收

- 高置信度人格特征都有证据。
- 画像特征、共同记忆与对话范例可以分别管理。
- 构建任务失败后可以从安全检查点重试。
- 用户能否定或锁定人格特征。

## 阶段 4：聊天运行时

### 目标

生成具有人格一致性、关系连续性和长期记忆的回复。

### 工作项

- 会话创建与消息保存。
- 场景识别。
- 记忆查询规划。
- 结构化画像查询。
- 情景记忆混合检索。
- 真实范例检索与重排。
- Token 预算和上下文组装。
- 模型流式生成。
- 人格一致性检查。
- 身份和内容安全检查。
- 回复持久化。
- 异步候选记忆提取。

### 交付物

- 聊天 API。
- WebSocket 或流式 HTTP 接口。
- Web 聊天页面。
- 调试追踪页面。
- 基线与人格方案的对比报告。

### 验收

- 多轮会话可以恢复。
- 人格版本固定在一次运行期间，不会中途改变。
- AI 回复不会自动进入真实范例库。
- 用户 A 无法访问用户 B 的会话和记忆。
- 可追踪一次回复使用了哪些记忆与范例。

## 阶段 5：反馈与持续补全

### 目标

形成可控的人格迭代闭环。

### 工作项

- 像 / 不像反馈。
- 原因标签。
- 理想回复输入。
- 反馈聚合。
- 人格差异分析。
- 候选更新生成。
- 人工审核。
- 人格版本发布。
- 回滚。
- 更新前后离线评估。

### 交付物

- 反馈组件。
- 反馈列表。
- 候选更新审核页面。
- 人格版本页面。
- 版本差异报告。

### 验收

- 单次负面反馈不会直接重写人格。
- 每项更新能追踪到反馈或新增真实聊天。
- 发布新版本前能够运行回归评估。
- 回滚后新会话使用旧版本。

## 阶段 6：安全、隐私与内测发布

### 目标

达到邀请制内测条件。

### 工作项

- 完整权限检查。
- 文件病毒和压缩炸弹防护。
- 敏感字段加密。
- 删除任务和索引清理。
- 审计日志。
- 速率限制。
- 模型费用预算。
- 内容安全策略。
- 备份与恢复演练。
- 数据隔离测试。
- 风险文案和用户协议页面。

### 交付物

- 内测部署环境。
- 运维手册。
- 数据删除手册。
- 安全测试报告。
- 评估报告。
- 内测用户说明。

### 验收

- 完成 PRD Definition of Done。
- 完成跨用户越权测试。
- 完成删除验证。
- 完成人格回滚演练。
- 关键指标可在监控系统查看。

## 阶段 7：微信小程序接入（V1.1）

### 目标

让用户在微信小程序中使用已经验证的陪伴人格。

### 工作项

- 注册并配置小程序。
- 域名、HTTPS 和备案准备。
- 小程序登录与现有账号绑定。
- 小程序聊天 UI。
- 渠道令牌和身份映射。
- 流式体验适配。
- 平台审核所需隐私与内容安全说明。
- 消息失败重试与幂等处理。

### 交付物

- 微信小程序代码。
- 微信渠道适配模块。
- 账号绑定页面。
- 审核材料。
- 灰度发布配置。

### 验收

- 同一用户在 Web 与小程序看到一致人格版本和会话。
- 微信渠道故障不影响核心人格服务。
- 消息重试不会产生重复 AI 回复。

## 4. 并行工作流

以下工作可以并行：

### 产品与设计

- 用户流程。
- 人格审核界面。
- 聊天反馈交互。
- 风险提示。

### 后端

- 导入管线。
- 人格构建。
- 聊天运行时。
- 权限与审计。

### 前端

- 项目管理。
- 导入与构建进度。
- 人格管理。
- 聊天与反馈。

### AI 与评估

- 提取 Schema。
- Prompt 和模型策略。
- 检索排序。
- 测试集与基线。
- 版本效果评估。

## 5. 团队配置建议

最小团队：

- 1 名全栈或后端主程。
- 1 名前端工程师。
- 1 名 AI / 数据工程师，可由后端兼任。
- 1 名产品设计负责人，可兼职。

单人开发时的优先顺序：

1. 后端数据模型。
2. 导入 CLI。
3. 人格构建脚本。
4. 简单聊天 API。
5. 最小 Web 管理界面。
6. 反馈和版本。
7. 安全与部署。
8. 微信小程序。

## 6. 测试策略

### 6.1 单元测试

- 各格式解析器。
- 消息去重。
- 身份和租户过滤。
- 记忆冲突。
- 人格版本发布。
- Token 预算。

### 6.2 集成测试

- 上传到人格构建完整流程。
- 聊天到记忆提取流程。
- 反馈到人格版本流程。
- 删除到索引清理流程。

### 6.3 AI 评估

- 人格特征提取准确性。
- 关系模式提取准确性。
- 真实范例检索 Recall@K。
- 人格一致性。
- 错误知识使用率。
- 风格夸张率。

### 6.4 安全测试

- 跨租户 IDOR。
- 提示注入记忆。
- 恶意上传文件。
- 压缩炸弹。
- 超大输入。
- API 重放。
- 删除后残留。

## 7. 发布策略

### 7.1 开发环境

- 使用脱敏样本。
- 可以启用调试追踪。
- 不连接真实微信渠道。

### 7.2 预发布环境

- 使用与生产相同的数据库扩展和队列。
- 执行迁移、备份和回滚演练。
- 使用模型预算限制。

### 7.3 邀请制内测

- 人格数量和消息量配额。
- 限制公开分享。
- 重点监控删除、越权和人格冒用。
- 每周审查负面反馈最高的场景。

## 8. 项目风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 聊天记录格式不稳定 | 导入失败 | 标准中间格式；解析器独立版本化 |
| 人格提取成本过高 | 构建慢、费用高 | 分批、缓存、确定性统计优先 |
| 人格夸张 | 用户觉得“表演感”强 | 限制口头禅频率；场景化范例 |
| 模型自我污染 | 越聊越不像 | AI 输出隔离；更新必须有外部证据 |
| 错误记忆 | 冒犯或误导用户 | 来源、置信度、有效期、用户编辑 |
| 数据泄漏 | 严重安全事故 | 强制租户过滤、权限测试、加密和审计 |
| 微信接入受限 | 渠道延期 | 核心服务与渠道解耦；Web 先上线 |
